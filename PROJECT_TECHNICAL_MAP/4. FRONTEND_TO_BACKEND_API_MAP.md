## 2. In-Depth Lifecycle of Core API Operations

### 2.1 User Login Flow
- **Called In:** [`LoginForm.jsx`](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/components/login/LoginForm.jsx) (`handleSubmit`, Line `24`)
- **Trigger:** User clicks `"Sign in to Workspace"` button on `/login`.
- **Payload Sent:**
  ```json
  {
    "identifier": "coordinator@cdac.in",
    "password": "••••",
    "role": "owner"
  }
  ```
- **Backend Route & Controller:** `authRoutes.js:17` → `authController.js:82` (`login`).
- **Response Received:**
  ```json
  {
    "success": true,
    "message": "Login successful",
    "token": "eyJhbGciOi...",
    "user": {
      "id": "CC-208",
      "username": "coursecoordinator",
      "email": "coordinator@cdac.in",
      "name": "Course Coordinator",
      "role": "owner",
      "roleTitle": "Course Coordinator"
    }
  }
  ```
- **Where Stored:**
  - `localStorage.setItem("qms_token", res.token)`
  - `localStorage.setItem("qms_user", JSON.stringify(sessionUser))`
  - React State: `app.loginUser(sessionUser, res.token)` in `AppContext.jsx`.
- **Consuming Component / View:** Redirects to `/process-owner/dashboard`, updating `Sidebar`, `Header`, and dashboard widgets.

### 2.2 Document File Upload Flow
- **Called In:** [`Documents.jsx`](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/pages/Documents.jsx) (`handleUploadSubmit`, Line `88`)
- **Trigger:** User opens `"Upload Controlled Document"` modal, selects a binary file (`.pdf`, `.docx`), fills title and process, and clicks `"Upload to Repository"`.
- **Payload Sent:** `multipart/form-data`:
  - `file`: Binary file stream
  - `title`: `"Course Delivery Template"`
  - `type`: `"Templates"`
  - `process`: `"Course Management"`
  - `description`: `"Official C-DAC course laboratory guide"`
- **Backend Route & Controller:** `documentRoutes.js:26` (via Multer `upload.single("file")`) → `documentController.js:185` (`uploadDocument`).
- **Disk & DB Persistence:**
  - File stored in `backend/uploads/<timestamp>-<filename>.pdf`
  - Record saved to MongoDB `Document` collection and `backend/database/documents.json`.
  - Audit log created: `"File '...' uploaded for document '...' by Course Coordinator"`.
- **Response Received:**
  ```json
  {
    "success": true,
    "message": "Document and file uploaded successfully",
    "document": {
      "id": "DOC-009",
      "name": "Course Delivery Template",
      "fileUrl": "/uploads/1795596000-Course_Delivery.pdf",
      "fileSize": "142.5 KB",
      "status": "Under Review"
    }
  }
  ```
- **Where Stored:** Prepend to `documents` state in `AppContext.jsx`.
- **Consuming Component:** Rendered dynamically in [`DocumentTable.jsx`](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/components/tables/DocumentTable.jsx) with download and action buttons.

### 2.3 Task Status Update Flow
- **Called In:** [`TaskTable.jsx`](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/components/tables/TaskTable.jsx) (`handleStatusChange`, Line `45`)
- **Trigger:** User changes the status dropdown of a task from `"In Progress"` to `"Completed"`.
- **Payload Sent:**
  ```json
  {
    "status": "Completed"
  }
  ```
- **Backend Route & Controller:** `taskRoutes.js:17` → `taskController.js:135` (`updateTaskStatus`).
- **Response Received:**
  ```json
  {
    "success": true,
    "message": "Task status updated in database successfully",
    "task": {
      "id": "TASK-001",
      "status": "Completed"
    }
  }
  ```
- **Where Stored:** Updated in `tasks` array in `AppContext.jsx` and `tasks.json` on disk.
- **Consuming Component:** Inline status badge updates to green (`Completed`); `OverviewWaveChart` and `dashboardStats` compliance metrics dynamically recalculate.
