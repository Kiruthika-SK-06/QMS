#### Step 4: Create the Frontend API Service
- **Path to create:** `QMS-main/src/services/riskService.js`

- **Register in:** `backend/models/index.js`

    title: { type: String, required: true },
    process: { type: String, required: true },
    severity: { type: String, default: "Medium" },
    mitigationPlan: { type: String },
    status: { type: String, default: "Open" }

  export default Risk;

#### Step 6: Create Backend Controller & Routes
- **Create Controller:** `backend/controllers/riskController.js` (implement `getAllRisks`, `createRisk`)
- **Create Route:** `backend/routes/riskRoutes.js`
- **Mount in Server:** [backend/server.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/server.js)
  ```javascript

  // ...

  ```

## 3. How to Change or Extend User Roles and Permissions

### Where Roles Are Configured

1. **Database Schema:**
   - [backend/models/User.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/models/User.js)
   - Field `role`: Valid values include `head`, `coordinator`, `owner`, `admin`, `auditor`.
   - Field `privileges`: Array of explicit strings (e.g., `["manage_users", "approve_mrm", "upload_mom"]`).

2. **Database Seeder:**
   - [backend/config/seed.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/config/seed.js)
   - Inspect `defaultUsers` array to see how initial demo credentials map to roles.

3. **Backend Middleware Enforcement:**
   - [backend/middleware/authMiddleware.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/middleware/authMiddleware.js)
   - Function `requireRole(allowedRoles)`:
     ```javascript
     export const requireRole = (allowedRoles) => (req, res, next) => {
       if (!req.user || !allowedRoles.includes(req.user.role)) {
         return res.status(403).json({ success: false, message: "Permission Denied" });
       }
       next();
     };
     ```
   - Protect any route by adding `requireRole`:
     ```javascript
     router.post("/:id/approve", authenticateToken, requireRole(["head"]), approveMRM);
     ```

4. **Frontend Protected Routes:**
   - [QMS-main/src/App.jsx](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/App.jsx)
   - Component `<ProtectedRoute allowedRoles={[...]}>` checks `currentUser.role` against the prop array. If not authorized, it renders an "Access Denied" notice.

5. **Frontend Navigation Filtering:**
   - [QMS-main/src/components/Sidebar.jsx](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/components/Sidebar.jsx)
   - Filter condition:
     ```javascript
     const visibleItems = navItems.filter(item => 
       !item.roles || item.roles.includes(currentUser?.role)
     );
     ```

## 4. How to Add a Brand New API Endpoint

### Scenario: Adding an endpoint to batch-download all approved documents as a ZIP archive

#### Step 1: Create the Controller Method
- **File to edit:** [backend/controllers/documentController.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/controllers/documentController.js)
- **Implement function:**
  ```javascript
  export const downloadBatchApproved = async (req, res) => {
    try {
      const approvedDocs = await Document.find({ status: "Approved" });
      // Zip logic or manifest generation
      res.json({ success: true, count: approvedDocs.length, files: approvedDocs.map(d => d.fileUrl) });
    } catch (err) {
      res.status(500).json({ success: false, message: err.message });
    }
  };
  ```

#### Step 2: Register the Route
- **File to edit:** [backend/routes/documentRoutes.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/routes/documentRoutes.js)
- **Add route line:**
  ```javascript
  router.get("/batch/approved", authenticateToken, downloadBatchApproved);
  ```
  *(Important: Place `/batch/approved` before `/:id` so Express doesn't treat `batch` as an ID parameter).*

#### Step 3: Add Frontend Service Method
- **File to edit:** [QMS-main/src/services/documentService.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/services/documentService.js)

## 5. How to Modify the Document Approval Workflow

### Current Approval Logic
1. **Initial Upload:** Document status is set to `"Under Review"` by default.
2. **Review Action:** Trust Head or authorized officer triggers `PATCH /api/documents/:id/status` with `{ status: "Approved" | "Rejected", comments: "..." }`.
3. **Audit Trail Recording:** An activity entry is created, and notifications are distributed to the document owner.

### Key Files Controlling This Flow
| Purpose | File Path |
|---|---|
| Frontend Review Modal & Buttons | [QMS-main/src/pages/DocumentManagement.jsx](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/pages/DocumentManagement.jsx) (Look for `handleStatusChange` or `handleReviewSubmit`) |
| Frontend API Call | [QMS-main/src/services/documentService.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/QMS-main/src/services/documentService.js) (`updateStatus`) |
| Backend Route | [backend/routes/documentRoutes.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/routes/documentRoutes.js) (`PATCH /:id/status`) |
| Backend Controller | [backend/controllers/documentController.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/controllers/documentController.js) (`updateDocumentStatus`) |
| Mongoose Document Model | [backend/models/Document.js](file:///c:/Users/WBL/Downloads/QMS-main-updated/backend/models/Document.js) (Fields: `status`, `reviewComments`, `updatedBy`) |

### How to Add a Second Reviewer (e.g. QMS Coordinator Review before Trust Head Sign-off)
1. In `backend/models/Document.js`, change `status` enum or add `reviewStage: { type: Number, default: 1 }`.
2. In `backend/controllers/documentController.js`:
   - If `stage === 1` and user is `coordinator`, set status to `"Recommended for Final Approval"`, `stage = 2`.
   - If `stage === 2` and user is `head`, set status to `"Approved"`.

## 6. How to Modify the Management Review Meeting (MRM) Workflow

### Current 4-Stage State Machine
- **Stage 1:** Meeting Scheduled (`status: "Scheduled"`)
- **Stage 2:** Agenda Distributed via Email (`status: "Agenda Circulated"`)
- **Stage 3:** Meeting Conducted & MoM Document Uploaded (`status: "MoM Uploaded / Pending Review"`)
- **Stage 4:** Trust Head Approval & Endorsement (`status: "Approved"`)
